# Contributing

Thanks for helping. MTScraper is small on purpose: plain ESM JavaScript, no build step, Node 20 or newer.

## Set up

```bash
git clone https://github.com/mazprotech/mtscraper.git
cd mtscraper
npm install
node bin/mtscraper.mjs setup   # Chromium for --js, --click, buttons and the PDF tests
npm test
```

## Tests

`npm test` starts a small HTTP server inside the test process and crawls it. It covers the page cap, link following, the `--follow` filter, PDF text and table extraction (the PDF is generated by Chromium during the test), click-mode safety (a Delete button and a form button must never be clicked), the PDF layout heuristic, and an MCP round trip over stdio.

To add a case, add a page to the `pages` map in `tests/crawl.test.mjs` and a `test(...)` that calls `run({...})`. Every change to crawling, extraction or the CLI needs a test. CI runs the suite on every push and pull request.

## Code notes

- `src/crawl.mjs` is the crawler, `src/extract.mjs` turns HTML and PDFs into records, `src/mcp.mjs` is the MCP server, `bin/mtscraper.mjs` is the CLI.
- Keep the record shape stable: `url`, `title`, `view`, `type`, `text`, `tables`, in that order, for every record.
- Keep robots.txt handling and the click-mode guards. They are the reason people can trust the tool.
- Comments explain why, not what. A known shortcut gets a `shortcut:` comment that says when to upgrade it.

## Proposing changes

- Bug: open an issue with the command you ran and what you got, or send a pull request with a failing test.
- Feature: open an issue first so we can agree on scope. Pull requests with a test are welcome after that.

## Out of scope

We will not accept changes that log in to sites, solve or bypass CAPTCHAs or bot protection, rotate proxies, or ignore robots.txt.
